## HyperPortal 0.1.0

### 拖拽触发与防误触

- 统一为一个「拖拽半径」（默认 24dp，8–48dp 可调）：圆心是长按成立时的位置，**圈内不出影子**，手指拖出圈才真正开始一次系统拖拽
- 长按成立前的手指容差不再有隐藏的 80px 下限 —— 高密度屏上原来 8–26dp 的滑块是死区，现在整段都有效
- 长按期间允许手指在圈内微动，超出即判定为滑动并放弃本次长按，不会再把滚动误判成拖拽
- 修复长按触发时间调短时（≤550ms）AES 原生 450ms 触发绕过防误触的问题

### 误发保护

- 新增「同窗口拖拽不投递」开关（默认开启）：把拖拽拖回**起拖的那个窗口**松手时，不再把 drop 交给应用，阴影按未消费处理并原生回弹 —— 微信不会再把误拖出的消息直接发出去
- 同应用的**另一个窗口 / 另一个聊天**不受影响，仍然可以正常接收（分屏、小窗、双开场景）
- 拖出半径后再拖回圈内，影子会变暗提示「松手取消」；圈内松手且在源窗口，同样走回弹
- WebView 不再消费 `ACTION_DROP`，拖到 WebView 上松手按未消费处理，阴影正常飞回

### WebView

- 与 ColorOS 对齐的 WebView 识别与内容抽取：按触点位置取页面里的文本、图片与链接，而不是把整个 WebView 当成一块容器

### 长按命中（图文混排）

- 新增**规则优先**：内置 ColorOS 17 的视图规则表（`sys_view_drag_list.xml` 归约，2107 条 / 149 个应用），命中规则时按规则声明的模态抽取，不再让「文字」抢走「图片」
- 没有规则的应用回退到点锚定：容器层先沿触点下钻到真正被按住的子视图，只有没有任何子视图覆盖触点时才做整格文本聚合
- Compose 页面（B 站评论区、DeepSeek 等）：模态跟随手指位置，文本只有在手指真的落在文本节点里才优先；不再把整块评论区当图片裁走
- Telegram 及 ExteraGram / ExteraLess 等派生客户端：同一条消息里的图片与配文按手指位置区分；大图页能取到原图而不是配文

### 动图保存与分享

- 微博大图页的 GIF 可以原样保存了（实测 19.8 MB、完整帧，不再是首帧静图）
- 同一张图经 Glide 渲染时也能取回：从内存里的编码缓冲区直接还原（实测与源文件字节数一致）
- 动图探测不再限定应用：只要有动图 drawable（`*GifDrawable` / `*AnimatedDrawable` / `*MovieDrawable` / `*WebpDrawable` / `*ApngDrawable`）就会尝试取回原始文件
- 取回时优先用真实文件；只有拿不到路径时才落到「重建临时文件」，临时文件只保留最近几份

### 已知限制

以下几个位置的动图**仍然只能得到静图**，属于渲染方式限制：

- 微信「表情包」「小程序」整页预览（Flutter 渲染，画面在独立 surface 上）
- QQ 表情包网格缩略图（新版 Libra 图库解码后丢弃编码数据，本地也不缓存）
- 小红书实况图（是 MP4 视频，不属于动图）

同一个表情在 QQ 里点开大图再拖，可以存成动图。

### 安装包

- `HyperPortal.apk`：主应用与 LSPosed 模块
- `AES-patched.apk`：替换系统 ContentCatcher 的 AES Hook
