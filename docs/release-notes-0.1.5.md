## HyperPortal 0.1.5

本次更新针对普通滑动和静置后首次滑动中的额外开销，修正滚动误触发长按提取的路径。

### 滚动与长按

- 手指移动超过系统滚动阈值后，取消本次 WebView 预取、长按兜底、原生 AES 提取和迟到的网页结果，避免信息流滑动期间继续遍历页面。
- 滑出阈值后再滑回原位置，也不会恢复本次长按；下一次按下可以正常重新识别。
- 原生 AES 的长按计时器被拒绝时，在遍历视图树之前退出。
- 长按完成后，仍需移出设置中的拖拽圆圈才开始拖拽；圆心使用长按完成时的位置。
- 同步输入分发与主线程计时器之间的手势状态。

### 首次触摸开销

- 广播接收器注册移至后台，并在拦截器创建时提前初始化。
- 已有配置过期后的刷新延至抬手后，减少与滑动起始帧争用资源；设置变更广播仍即时生效。
- 关闭调试日志时跳过触摸事件字符串构造，减少连续滑动中的重复对象分配。

### 构建与验证

- 根据 smali 源码内容更新 DEX 缓存，防止修改拦截器后仍打包旧代码。
- 云端发布运行手势和构建缓存回归测试，校验两个 APK 的签名，并保留主应用的 R8 映射文件。
- 发布标签、应用版本和发布说明保持一致；主应用版本为 `0.1.5`（versionCode 11），AES versionCode 更新为 `1000000049`。

已有修复版的单次被动采样中，181 次 AES 触摸分发平均约 0.020 ms，最大约 0.066 ms。
该样本来自小米应用商店，尚不能代表酷安、微博等应用静置后首次滑动的完整前后对比；相关场景仍需真机反馈。

### 安装包

- `HyperPortal.apk`：主应用与 LSPosed 模块，云端 R8 构建。
- `AES-patched.apk`：ContentCatcher 的 AES Hook，保持未混淆。

更新 AES 后，请手动彻底关闭并重新打开目标应用，使其加载新的拦截器代码。
建议静置 10–30 秒后分别测试快速滑动、慢起步滑动，以及文字／图片长按拖拽与取消回弹。
